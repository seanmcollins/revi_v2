# Security

## Status of this codebase

Revi is a research and development-stage codebase. There is **no deployed instance**,
no hosted service, and no production data anywhere in this repository — the warehouse
it queries is synthetic data generated by `make warehouse`.

Its authentication posture is deliberately open for local development: a dev tenant is
accepted without an identity provider, and there is no user store, no login, and no
authorization beyond the tenant boundary. That is a stated design position for this
stage, not an oversight.

Read [`docs/acceptance-walkthrough.md`](docs/acceptance-walkthrough.md) — the
**"Not built — name it before a security review does"** section enumerates the gaps
honestly and in more detail than a report is likely to: bearer-token weaknesses, the
absent audit log, missing rate limiting and input caps, the undefined PHI/BAA scope,
and the read-write warehouse connection.

Do not run this against real patient data.

## Reporting

Open a GitHub issue. Given that nothing is deployed, there is no embargo process and
nothing to disclose responsibly against — a public issue is the right venue.

If you find something genuinely surprising (a way to cross the tenant boundary, an
evidence-provenance claim the system cannot actually back), that is interesting
regardless of deployment status and worth an issue of its own.
